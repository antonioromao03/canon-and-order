# Annotation Guide

How to build one gold file: the correct timeline for one universe, every field checked
against a source. The rules come from the product spec, which started as the rules of an earlier
prototype; this guide turns them into annotation decisions. When the two disagree,
fix this guide.

## Workflow (One Universe)

1. Copy `gold/template.yaml` to `gold/universes/<slug>.yaml` (slug of title + year,
   e.g. `breaking-bad-2008`). Set `split`, `cutoff` and `continuity`.
2. **List works first, dates second.** Start from list sources (franchise page, episode
   list, studio page), then search each category separately: films, TV seasons, specials
   and crossovers, shorts and web series, home-release extras, in-universe promos.
   Obscure items rarely show up in one broad search.
3. Date every work and every piece (see Dates). Record a citation for each claim.
4. Write the rows by hand, applying the row rules below. Do not run the rule engine to
   produce them: the gold rows are what the engine is tested against.
5. Add 2–5 `checks` for the rules this universe exercises. A `before` check that tests
   plain date order uses `rule: sorting`; use `companion` only when one side is a
   companion row.
6. Run `uv run python -m canon_and_order.gold validate` until it passes.
7. Log `time_spent_minutes`, set `annotated_on`, then `status: verified`. Add a line to
   `gold/CHANGELOG.md`.

**Time box:** about 30 minutes for a standalone film, up to 3 hours for a series with
extras. If a fact cannot be settled in reasonable time, record what you can confirm, add
a flag, and move on.

## Starting from a Draft

Exported artifact timelines may seed a file (`seeded_from_draft: true`), but they were
generated by an LLM and are not ground truth. Check every field as if it were blank.
The draft error rate is not measured in v1: the draft-seeded files recorded no error
counts. To measure it later, note in each commit how many draft errors you corrected.

## Source Priority

1. Official studio, network or streamer pages and press releases.
2. TMDB typed release dates (premiere, limited, theatrical, digital, physical, TV) for the
   country of origin.
3. Wikipedia episode lists and franchise articles (follow their references when they matter).
4. TVmaze, TheTVDB.
5. Fan wikis and fan sites: only to find leads, or when nothing better exists (then flag).

## Decisions

### Scope and Continuity

- The universe is the continuity the input belongs to, **as its current rights holder
  treats it**. Write that boundary in `continuity`.
- The input year picks the continuity (Battlestar Galactica 1978 vs 2004).
- Sequels, prequels, spinoffs and same-continuity works are in.
- **Crossover** from another continuity: the crossover work is in; the rest of the other
  continuity is out and goes in `exclusions`.
- **Semi-canon** (ambiguous, contested or retconned canon): in, with `canon: semi_canon`.
- Out, and listed in `exclusions` when notable: reboots, remakes, foreign adaptations,
  decanonised material, trailers, featurettes, recuts and extended cuts (unless a
  substantially different work), documentaries, real-world talk shows, fan works, and
  anything not on a screen (games, comics, novels, websites, social posts).
- In-universe promos made by the rights holder are in (`promotional_content`).

### Works and Pieces

- One work per atomic release: a film, a season (or officially announced part), a
  miniseries, a special, a short, a web-series batch, a set of promo pieces.
- A season is split into parts (separate works) only when the studio presents parts or
  halves, or when batches are separated by a gap of 3+ months.
- Pieces are numbered in release order. If there is no official collective title, use a
  short descriptive name and add the `descriptive_name` flag.
- Set `parent` when supplementary content was made for a specific TV season (promotes
  it, is tied to its episodes, or comes from the show). A link to the wider universe is
  not enough.

### Dates

- The first date the general public in the **country of origin** could watch it, local
  time: wide theatrical, streaming, broadcast or home-video release. Festival, red-carpet
  and fan-screening premieres do not count.
- A limited public run (a film opening in a few cities) or an early streaming opening
  counts: the public could watch it. If sources commonly give the later wide date, add
  `date_conflict` and name that date in `notes`.
- Seasons: premiere of the first episode. Piece sets: the first piece. Home-release
  extras: the disc or digital release date.
- Write `YYYY-MM-DD`; if only the month or year is confirmed, write `"YYYY-MM"` or
  `"YYYY"`. **Never fill in a guess.**
- Sources disagree: use the best-supported date, add `date_conflict` and explain in `notes`.
- Unconfirmed: `date_unconfirmed` (or `piece_dates_unconfirmed` for pieces).
- Co-productions: say in `notes` which country you treated as the origin and why.

### Rows

- Default: one row per work; a work's row label is its official title plus season,
  part, or piece range.
- **Splitting:** when a single-release entry (film, special, standalone short,
  crossover episode, all-at-once season) comes out while a multi-episode work is still
  releasing, split that work at that date. Pieces before stay in the first row; pieces
  after form a new row after the single release. Split however short the gap, and at
  every such release.
- **Supplementary content never splits a TV season or miniseries.** Made for that show →
  companion row; otherwise an ordinary row in date order after the season row it falls
  within.
- **Companion rows** (`role: companion`): a work whose `parent` is a season becomes a
  companion row when its release span (first to last piece, or its release date if it has
  no pieces) overlaps the season's run (premiere to finale, both days included). A single
  short or an all-at-once release counts, not only sets. The row is dated by its first
  piece: if that came out on or before the premiere, the row goes directly before the
  season row; otherwise directly after it. If the season is split, split its companion
  rows at the same point. A parented work released wholly outside the run is an ordinary
  row in date order.
- Two multi-episode works releasing over the same period do not split each other; keep
  each whole and sort by premiere.
- **Sorting:** oldest first. Same day: actual release order if known; otherwise
  supplementary before main; otherwise the one whose run began earlier. Flag
  `same_day_order_unconfirmed` when you had to fall back.

### Upcoming

- List a title in `upcoming` only when the rights holder has officially announced it
  (greenlit, renewed or dated), even if it is untitled or undated: `expected` is as
  precise as the announcement, down to `"TBA"`.
- Development reports, rumours and rights purchases stay out; mention them in `notes`
  with a source.

## Evidence

Every work needs at least one citation before the file is `verified`:
`url`, `accessed` (date), `supports` (which fields it backs) and a short `snippet`
(under 15 words, paraphrase if longer). Prefer one list page that covers many entries
over many single-entry pages.

## Flags

`date_conflict`, `date_unconfirmed`, `piece_dates_unconfirmed`,
`same_day_order_unconfirmed`, `canon_unclear`, `descriptive_name`, `todo`.
Flags are not errors: they record honest uncertainty, and the evaluation can report
results with and without flagged items.

## Checklist before `status: verified`

- [ ] Every category searched separately (films, seasons, specials, shorts, web, home release, promos)
- [ ] Every work and piece dated or flagged; no guessed day or month
- [ ] Every work has a citation
- [ ] Rows follow splitting, companion and sorting rules; split works cover each piece once
- [ ] Notable exclusions listed
- [ ] 2–5 checks added
- [ ] Validator passes; CHANGELOG updated
